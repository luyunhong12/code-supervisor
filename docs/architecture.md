# 通用结构与拆分规则（规范版本 1.0）

这是一份新整理的结构规则，不是原先重复文档的改名副本。实际业务包的职责由各项目文档定义。

1. 按稳定的业务职责和变化原因划分模块，不按任意行数拆分。
2. 项目明确底层、业务层和集成层；依赖方向保持一致。底层不反向依赖入口或集成模块。
3. 配置解析与校验放在边界，内部使用已校验的数据；避免多处维护同一默认值和规则。
4. 将纯计算与文件、网络、进程和设备操作分开，使计算能独立测试。
5. 公共接口写清参数单位、状态修改、失败行为和资源所有权；不要让调用方依赖隐藏顺序。
6. 两段代码相似只是审查线索。确认表达同一业务规则后再共享，避免将不同需求强行耦合。
7. 首先明确共享状态的所有者；能独立的数据不共享，需要共享的数据明确写入者和同步机制。
8. 重构前固定可观察行为，重构后验证；不以降低函数行数或指标为唯一目标。
9. 跨模块接口变化同步更新消费者、配置和测试；兼容性要求由项目明确。
10. 不为单次调用增加无必要的抽象、包或接口，不为规避检查将逻辑藏进配置或动态调用。
11. 生成物、第三方代码与自有源码分别标识；检查范围应可追溯，不通过排除核心源码消除报告。
12. 文档和代码矛盾时报告矛盾。项目明确且有理由的约定可以覆盖通用默认值。

## 执行边界

职责是否合理仍由 AI/人工结合代码审查。机器端已实现显式 Python 模块和 C++ include 禁止依赖规则。
规则须由项目明确声明，不能把现有依赖全部自动认定为正确；动态加载不在该静态检查范围内。
